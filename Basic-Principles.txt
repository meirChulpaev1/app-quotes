


1.
git
מערכת לניהול גרסאות יתרונות של גיט ממשק נוח לעבודה בצוות מסודרת כמו הצגת היסטוריה 
אני יכול להציג שם שינוים חזרה והצגת גרסאות קודמות 




2.
Repository
"התיקייה הראשית" של הפרויקט
.git – תיקייה שנמצאת בראשית כל Repository ובה כלל הגדרות הGit





3.
Branch
אוסף של קומנטים גרסאות שונות של הקוד המתקימים במקביל לגרסאות ברנצים אחרים 
מאפשרים לך לעבוד על חלקים שונים של הפרויקט, כמו תכונות חדשות או תיקוני באגים, מבלי להפריע לענף הראשי. 
בעצם משתמשים בו בפרויקט שהרבה עובדים עליו אם הוספות שינויים תמידים ואפשר לפתח במקביל בלי לפגוע בקוד המקורי ואחרי זה אחרי שאושר לי אני מוסיף אותו למקורי 




4.
Conflict 
זה כמושג כאשר שינויים שנעשו מאוסף של בראנצים מתנגים אחד בשני זה יכול לקרות במקרה ששני מפתחים עובדים על אותו  בראנץ 
ועושים בו שינויים או מוסיפ או מוחקים ומשנים את אותו קובץ 
במקרה שזה קורה אם מדוב בדברים שונים ששינו אז כל אחד ישים את זה את הקומנט שלו במקום אחר בבראנץ כמובן מסודר ושלא יתקע אחד בשני  


ואם זה שינוי על אותו דבר ששולחים pull reqest יבדקו לפני השילוב בקוד איזה אחד שיך יותר 

5.


head 

סימון לקומינט הנוכחי שאני נמצא אליו שאותו אני רוצה להוסיף לבראנץ מסוים










6.
 Remote

מתייחסת לגרסה של מאגר הפרויקט שלך, המאוחסנת ברשת או באינטרנט, ונבדלת מהמאגר המקומי שלך במחשב שלך.
היא משמשת כנקודה מרכזית לשיתוף פעולה וגיבוי 
מהמאגר המקומי שלך במחשב שלך הקוד שלי בעצם



7.
Pull Request
סוג של בקשה לבדיקת הקוד לפני שאני מעלה אותו ומאשרים לי למזג אותו בקובץ הראשי שינוים והוספות כלשהם


8

א
יוצר קומינט חדש עם השינויים שהוספתי
והודעת טקסת על מה ששיניתי /הוספתי
git commit –m “ the Changes i made ”


ב.

 לבראנץ מעלה את השינויים שהוספתי  נגיד חדש commit
git push origin [branch_name]

ג.

מושך תוכן מסויים נגיד מc omit מהגרסה המתקדמת שלו
git pull origin [branch_name]




 pull reqest ד
הוספתי עכשיו משהו חדש ועכשיו אני רוצה שיאשרו לי את זה ולשלב את זה בקוד אז 
   git pull origin [branch_name]



   ה.
fetch
מוריד בעצם את כל התוכן מהתקיה הראשית ,כל הבראנצים 
בלי לשנות אותם סוג של העתק רק
git fetch

ו.

rebase
שינוי בסיס הבראנץ הנוכחי לבסיס אחר 
git rebase [commit_number/branch_name]

ז.

stash
שומר את השינויים שנעשו בקומינט האחרון בצד 
git stash


ח.
add
שאני עכשיו משנה משהו מוסיף משהו מוחק משהו גיט לא מבצע שיניים אלו אוטמטית אני צריךך ממש להיג לו וזה התפקיד של הפקודה הזאת
        git add <filename>


  ט.
  rebase –i

נותן למשתמש את רשימה של הקומנטים שב rebase
אתה יכול להשתמש בזה שאתה רוצה לשנות את הרשימה לפי rebase
יכול לשמש לאיחוד commit
השימוש מששתנה אתה יכול להשתמש בזה למחיקת קומינט או לאיחוד וסידור שלהם

git rebase –i [start_commit]


9.

לאחר הפקודה rebase –i
    משנה את עץ השינויים על ידי ארגון מחדש של הקומיטים  מוחקת או ממזגת קומינטים תלוי בשימוש,
   במקום עץ מסועף ומבולגן  הוא מאפשר ליצור היסטוריה נקיה שבה ה הקומינט יופיעו בצורה ישרה
   שבה הקומיטים מיושרים בקו ישר על גבי בסיס קומיט משותף.
   פקודה זו נותן לנו את הגמישות לערוך, למזג או להסיר קומיטים, מה שמשפר את בהירות ההיסטוריה של הפרויקט.
לפני הפקודה העץ יראה כמו ענף אחרי הפקודה העץ יראה ישר בצורה לינראית וזה כיאילו בוצעו כל השינויים אחד אחרי השני על אותו בסיס
